# Hermes agent pin

## hermes-agent follows a release tag, bumped by Renovate

**Id:** 5e168215-1247-4263-afa0-3835499a7032
**Type:** decision
**Status:** active
**Evidence:** confirmed
**Source:** `renovate.json` (regex custom manager and `packageRules` entry); `modules/agents/hermes.nix`

The `hermes-agent` input is pinned to a GitHub release tag, `v0.22.4`. Renovate edits that tag in the declaration through a regex custom manager, and the nix manager is disabled for this dependency so the two cannot both claim it. The lock is regenerated by candidate preparation, since automation branches are exempt from `generated_files: check`.

**Alternatives:** follow the default branch, which rebuilds the agent on every upstream push and makes its updates indistinguishable from routine input moves; pin a commit sha, which loses the release boundary the tag draws and asks the regex to track revisions; keep the earlier PR-head pin, which existed only for a cold-store evaluation failure now handled by the fleet evaluator.
**Reason:** upstream releases often enough that a deliberate, reviewable bump beats tracking every push.
**Revisit when:** Renovate learns to update tag-pinned flake inputs without a custom manager, or the input is selected by a host again — that makes its evaluation part of every check rather than dormant.

## hermes-agent was pinned to an unmerged upstream PR head

**Id:** 6046b69e-3dcb-4842-a68c-eb9d046e04ed
**Type:** decision
**Status:** superseded
**Superseded by:** 5e168215-1247-4263-afa0-3835499a7032
**Evidence:** confirmed
**Source:** NousResearch/hermes-agent#141750 (issue) and #141834 (PR, head `68ce9ec9`)

The input was declared at `68ce9ec9`, the head of PR #141834, because upstream read `uv.lock` and the npm lock through filtered source paths at evaluation time, which a read-only cold-store evaluation cannot write. The pinned head also carried eleven days of upstream state beyond the two-file fix.

**Alternatives:** wait for #141834 to merge, which left CI red; remove the aspect; pin the PR base `0b10b9f8`, which lacks the fix.
**Reason:** the operator chose to unblock CI, accepting an unmerged upstream head.
**Revisit when:** superseded — the fleet's evaluation gate now primes source paths with a writable, IFD-disabled pass, so the workaround is unnecessary. #141834 was still open when the pin was retired, and the release tag this entry's successor names does not contain it.
